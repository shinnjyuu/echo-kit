# 团队共享文档与个人私有文档

从 0.3.0 起，Echo Kit 提供项目文档入口。`docs` 读取项目维护的文档；`skills` 和 `protocol` 读取当前工具版本随包分发的使用说明。

| 类型 | 共享文档 | 私有文档 |
| --- | --- | --- |
| 内容 | 团队流程、架构、复现方法、可共享结论 | 本机目录、个人环境说明、原始调试记录 |
| 默认入口 | `echo/README.md` | `.echo-kit/private/README.md` |
| 文件引用 | 相对路径，Markdown 链接相对当前文件 | 允许绝对路径 |
| Git | 应纳入版本管理 | 禁止被 Git 跟踪 |

私有表示本地、不提交，不表示加密。账号密码继续使用现有认证机制。共享结论必须能独立理解，不能只写“原始证据见某人的私有目录”。私有材料需要分享时，提炼结论、清理个人信息，再写入共享文档。

## 接入与发现

在已有 Echo Kit 工作区中执行：

```sh
echo-kit docs setup
echo-kit --json docs list
echo-kit --json docs show shared
echo-kit --json docs show private
echo-kit --json docs check
```

`setup` 创建缺少的入口和配置、补充忽略规则，不覆盖已有文档，不自动暂存或提交。返回 `created`、`reused` 和检查结果；新共享文件尚未加入 Git 时返回 `unverified`（退出码 2），不表示初始化没有执行。按任务授权处理共享文件后重新检查。

`list` 只返回入口、归属、存在性和 Git 状态。`show private` 是显式读取个人正文的入口，内容会返回调用者；Kit 不自动把正文写入报告或持久化日志。调用者也应避免把输出重定向到共享文件。缺失的私有入口可选；缺失的已配置共享文件检查失败。

尚未接入的旧工作区返回 `not_configured` 和接入提示，不会自动生成文件。`workspace check` 和 `doctor` 提供 `documents` 摘要，但不把文档检查结果加入业务检查。

0.4.0 起直接调用上述命令，默认检查并使用最新稳定版；加 `--offline` 可读取当前可用版本的文档而不联网。项目文档是项目自己维护的文件，不是工具版本快照。旧版项目入口需按[迁移说明](updates.md#已有项目迁移)主动更新。

## 保留已有目录结构

不必搬迁已有团队文档。在共享 `echo-kit.toml` 指定入口，路径相对工作区根目录：

```toml
[documents]
shared = "docs/development/README.md"
```

本机 `.echo-kit/local.toml` 单独指定个人入口：

```toml
[documents]
private = ".echo-kit/private/README.md"
```

私有入口也可配置本机绝对路径。实际值只写在本机配置，不复制到团队说明中。仓库外的私有文件必须已经存在，`setup` 不会替用户在仓库外创建目录或文件。本机入口配置本身也必须排除 Git。自定义的仓库内私有入口只为该文件增加忽略规则，引用的其他私有文件需另行忽略。已有忽略规则或嵌套规则产生冲突时按检查结果处理，不自动改写团队规则。

`shared` 只能出现在共享配置，`private` 只能出现在本机配置；environment 不允许设置 `documents`。来源检查使用原始配置，不能用本机覆盖来掩盖共享配置中的个人路径。共享入口必须位于工作区内且不能位于 `.echo-kit/` 中。

## 检查范围与结果

`docs check` 从登记入口递归跟踪本地 Markdown 引用，支持普通链接、引用式链接、图片和 HTML 的 `href` / `src`；代码示例中的 Markdown 链接不视为实际文件引用。网页 URL 和锚点不检查网络或标题是否存在。

共享引用必须是工作区内的相对路径。检查 Windows、UNC、POSIX、`file:` 和编码后的绝对路径，并解析符号链接以发现越界。非 Markdown 附件检查存在性与 Git 状态，不读取正文。发现指向 `.echo-kit/`、已登记私有入口或 Git 忽略文件的共享引用时，不沿该引用读取内容。

私有入口及其显式引用的本地 Markdown 文档会检查 Git 状态，支持绝对路径和 file URI；已从共享入口发现的文档仍归共享。只沿明确引用递归，不枚举个人目录。私有文件位于另一个 Git 仓库时，检查该仓库的跟踪状态。检查不扫描无引用文件或 Git 历史，不识别自然语言描述中的所有隐含依赖，也不代替内容保密审查。

| 结果 | 典型情况 | 退出码 |
| --- | --- | --- |
| `passed` | 已检查范围符合约定 | 0 |
| `failed` | 共享路径违规或断链；私有文件已跟踪、未忽略 | 1 |
| `unverified` | 未接入、共享文件未跟踪、Git 不可用、私有引用断链、正文疑似个人路径、读取或范围限制 | 2 |

确定违规优先于未验证。诊断包含 `code`、`path`、`status`，引用和正文问题还提供行号；不包含原文片段或私有正文。单文件最大 2 MiB，每次最多检查 500 个文件，达到限制返回未验证，不声称全量通过。行号为解析器定位的引用所在行，引用式链接通常定位到使用处。

`docs check` 不修改文档、Git 索引或历史。已经跟踪的私有文件即使加入 `.gitignore`，甚至工作区文件已删除，只要仍在索引中就会报错。由用户确认后处理索引和历史中的内容；工具不自动删除证据。

## AI 使用规则

开始工作时先发现并读取共享入口，再按任务需要读取个人入口。写文档前判断受众；个人说明可以补充本机事实，不能默默覆盖团队约定或扩大操作权限。发生冲突时说明冲突并遵循用户当前指令。

文档改动后运行 `docs check`。共享文档保留团队可复现的方法与结论，个人文档保留本机位置和原始记录。提交、推送和私有内容转为共享内容仍受当前任务授权约束。

## 工作区文档地图与目录规则（0.11.0）

这些入口发现整个 `--workspace`，不限于 `echo/`，不要求先运行 `docs setup`，但工作区必须已有 `echo-kit.toml`：

```sh
echo-kit docs map
echo-kit docs map --path backend/orders
echo-kit docs map --query 退款 --limit 20 --offset 0
echo-kit docs context backend/orders
echo-kit docs read backend/orders/docs/refund.md --start-line 1 --limit 200
echo-kit docs check --rules
```

地图只列 Git 已跟踪和未被忽略的未跟踪 Markdown 路径，不读取正文或生成摘要。默认逐层显示目录与文件，搜索按路径匹配，分页默认 20 项。私有材料、忽略项、目录符号链接／junction、子模块和嵌套仓库不遍历；无 Git 返回未验证，不扫描磁盘。每次最多检查 500 个候选，超限时总数仅代表已检查范围，需要缩小目录或显式读取已知文件。

`context` 按根目录到目标目录读取沿途准确命名的 `AGENTS.md`，不读兄弟目录。目标可为现有文件或目录；准备新建文件时传所在目录。README 和规则里的 Markdown 引用只提供后续入口，不展开正文。`AGENTS.override.md` 和大小写变体作为未验证候选列出，不模拟具体客户端的优先级。Kit 的目录链不代表客户端实际加载的全部指令，也不包含工作区外祖先或用户全局规则。

`read` 显式读取共享 Markdown，每次默认 200 行、最多 1,000 行。单文件上限 2 MiB；read 和 context 每次正文合计最多 64 KiB。未读完时返回未验证、未读行号及继续读取命令；单行超过预算需明确用本地编辑器查看。私有文件仍通过 `docs show private` 显式读取。

`check --rules` 检查发现的规则文件及直接本地引用，不递归读被引用文档、不执行命令、不访问网页、不判断业务语义冲突。断链和共享路径违规失败；Git 不可用、未跟踪规则、非标准规则文件名、边界不明或超限返回未验证。没有局部约束时不要求创建子目录 AGENTS.md。原来的 `docs check` 继续检查已登记共享／私有入口，两者均不自动阻断业务运行。

写入前分别判断受众、目录范围和内容类型：根 AGENTS.md 保留全项目规则，子目录 AGENTS.md 维护局部工作约束，详细需求／原型／业务规律独立成文并链接；跨模块知识只保留一份正文。发现放置不当时先说明建议，再在当前授权内整理与修复引用，CLI 不自动搬迁或重写。
