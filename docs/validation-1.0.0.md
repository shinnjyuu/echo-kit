# 1.0.0 验证记录

日期：2026-11-16。范围为 Echo Kit、隔离工作区和受控页面；未操作业务项目、个人浏览器资料或共享业务环境。此记录保存发行前验收；正式发行状态以官方 PyPI 为准。

原生运行包固定为 agent-browser 0.43.0 与 Chrome for Testing 157.0.8103.78，使用随包官方地址、大小及 SHA-256 校验。原生后端当前支持 Windows x64、Linux x64；macOS、ARM 暂不支持。

## 真实浏览器与生命周期

Windows 的七项受控生命周期检查通过：私有认证状态与目标地址、不同 actor 的上下文隔离、启动客户端退出后 worker 继续持有会话、崩溃后不自动重建或重放、定向关闭、急停忙碌及空闲会话、急停后重新启动。验证结束确认已知测试进程退出。

Windows 和 Linux Xvfb 已取得连续页面操作、表单与弹窗状态保留、截图、原型尺寸测量及关闭的真实证据。受控原型顶部区域为 62px，实际页面为 72px；对照报告具体尺寸差异并输出原尺寸并排图。上游在尺寸不同或像素相同时可能返回未实际写出的 diffPath，Kit 不将它当作可用图片，也不以尺寸不同产生的百分比宣称完成像素比较。

Linux 进程登记修复后的最后一轮真实测试包含十次热态观察，中位数约 321ms；关闭后确认没有遗留的测试 worker、daemon 或 Chrome。它与下面的 Windows 同机对比属于不同环境、不同轮次。

## 同机性能观察

在同一 Windows 主机上，以同一个本地受控 HTML 比较原生有头方式与明确选择的 Docker/Playwright 兼容方式。运行包和镜像已提前准备；冷启动不包含首次下载或镜像构建，热态数据分别取十次观察的中位数。

| 指标 | 原生有头 | Docker/Playwright 兼容 |
| --- | ---: | ---: |
| 冷会话准备 | 5.062 秒 | 4.188 秒 |
| 热态观察中位数 | 617ms | 109ms |
| 内存观测 | 约 935MiB，进程树 Working Set 加和 | 344.5MiB，Docker CLI 口径 |

两种内存口径不同，Working Set 加和还可能重复计算共享页；不能据此计算内存节省比例、整机占用或停止后可释放体积。这一轮原生方式也没有表现出更快的截图或冷启动。记录不承诺固定提速或内存节省；原生方式的产品收益是直接操作可见窗口，以及日常使用无需 Docker/noVNC。两种测试会话均已关闭，测试用兼容容器已定向移除。

## 安装包与待完成项

仓库外安装包已检查原生模块、运行清单、兼容 pixelmatch 资源、三套指南的精简／主题／完整读取及不覆盖导出。原生模块导入、CLI 查询和离线缺包诊断不依赖全局 Node/npm。另用官方 0.15.0 安装包的真实 startup、启动探测与子进程转发，验证了 1.0.0 版本、指南、新增 browser exec 命令及 session/reference 参数帮助；只有发行发现与候选安装位置受控，不能视为 PyPI 已发布的证明。

最终 Windows wheel 已从仓库外安装并通过真实有头闭环：快照句柄点击、文字／尺寸／样式读取、未保存输入和弹窗、异步图表与持续变化页面、固定基准采集、尺寸修正后的同基准复核、连续观察及 trace 收尾。该流式页面十次热观察中位数约 907ms，属于另一轮页面，不能替代上表的同机对照。

复验曾发现 Chrome 解压后的沙箱权限问题；现使用固定 Chrome ZIP 内、经过摘要核验的官方 setup.exe，只为公开运行目录配置专用 AppContainer／LPAC 的只读执行能力，成功码按固定版本校验为 78。未关闭 Windows 沙箱，未开放 profile、认证或 IPC 目录。官方后台计时、遮挡及渲染相关参数用于保持有头窗口后台操作；修复后的 engine 日志没有再出现该沙箱拒绝访问错误。自定义数据目录过长仍可能产生 Chrome GPU 缓存路径警告，不能将本轮受控成功扩展为任意 Windows 长路径支持。

补充真实 Windows 托盘检查已通过：独立原生 worker 自动唤起托盘、列出所属会话、调用同一定位入口激活自有 Chrome 窗口，测试会话及隔离托盘随后正常退出。托盘／会话／资源相关回归 110 通过；同操作手动退出不会被后续通知立即拉回。

Windows 托盘的人工点击、真实业务认证、企业 SSO、验证码、完整角色／租户权限，以及所有 Agent 宿主均未完成验证。受控 cookie/localStorage 导入不代表这些场景已经兼容。现有 Playwright 兼容模式的历史证据也不能自动扩展为原生证据。

原始日志、JUnit、截图、trace 和测量保存在本机忽略的验收产物目录；公开记录仅保留脱敏结论。核心回归使用 `uv run pytest`，真实浏览器和安装包检查为独立证据。相关入口为 [原生闭环示例](../examples/validate_native_browser.py)、[安装包检查](../tests/verify_visual_wheel.py) 和 [旧入口转发检查](../tests/verify_update_wheel.py)。
