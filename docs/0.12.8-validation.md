# 0.12.8 验证记录

本文记录 0.12.8 发布前的实现、核心与安装包验证。提交、推送和发布已获本轮用户授权；实际发布结果以发布流水线及[官方 PyPI](https://pypi.org/project/shinnjyuu-echo-kit/0.12.8/)复验为准。实施及发布前查询均返回 404，版本未占用。本轮未修改业务项目、全局工具入口、业务容器或已有导出副本。

## 实现范围

- 内部占用检查、服务状态、托盘及旧登记迁移先读取记录，只跳过明确 finished 且 held 为空的历史，再检查其余记录的进程。`operations list --unfinished` 提供同一未收尾视图；默认列表的历史范围、operations 数组结构及单条详情保留。
- 一次服务查询只计算各服务资源集合一次、各项目源码指纹一次；没有持久化索引或跨命令缓存。指定 `services status NAME...` 只检查并返回指定名称，未知名称先报错。启动汇总仍保留全量映射，不额外执行无关健康检查。
- `browser up/status` 增加 required_playwright_version，包含停止状态及外部连接失败；它是本包要求的客户端版本，不是探测出的外部版本。托管客户端不匹配时显示要求值和实际安装值。
- 同步中英文 README、AI 指引、三个 Skill、协议及随包副本、browser/cases/updates 主题与发行说明：复用入口、最小连接／身份／登录检查、页面与模型质量分别验证、模型少量样本先行、区分暂态与结构错误、报告实际消耗，以及日常调用与显式离线的区别。修正 AI 指引原有的默认用例化及固定人工确认旧口径。

## 核心与安装包验证

- Windows，Python 3.12.6 / pytest 8.4.2：`uv run --offline pytest -q`，**300 passed，13 skipped**，310.85 秒。
- Linux，Python 3.12.3 / 项目声明的 pytest 8（>=8,<9），已有测试镜像中的隔离容器：`uv run --no-sync pytest -q -p no:cacheprovider` 完整核心回归 **304 passed，9 skipped**，96.31 秒。此前镜像自带 pytest 9.1.1 的完整回归也为 304 passed、9 skipped，90.46 秒；最终补齐项目声明的测试依赖版本。源码只读挂载；本轮临时测试容器均已退出并清理。这是 Linux 容器核心证据，不代表 Linux 桌面、真实认证或真实浏览器验收。
- Linux 首轮相关回归曾有一次并发启动测试的服务提前退出（129 passed、1 failed、2 skipped）；该轮临时容器已自动移除，未取得足够日志确定原因。随后该单项通过，完整核心回归也通过；未改动该测试断言或通过产品自动重试掩盖失败。保留这一验证限制。
- 新增大历史测试：7,200 条完成记录、18 个服务、3 条未收尾记录，断言资源计算 18 次、操作进程检查 4 次（三个主进程及一个活跃子进程），历史文件全部保留。另覆盖空占用未结束、失效主进程、活跃子进程、损坏／不可读／非法记录、释放与共享降级后的新鲜状态，以及原有多进程抢占和共享／独占互斥回归。
- 服务筛选验证未触发其他服务健康检查；同项目源码在单次查询只计算一次，下一次查询重新计算；启动结果的未选中服务仍保留且 ready 为空。
- 三个 Skill 校验通过，公开协议与随包副本字节一致；119 个本地链接及锚点有效。`uv lock --offline` 仅提升本包版本，依赖要求不变。
- `uv build --no-sources --offline` 生成 wheel/sdist；仓库外独立环境安装 wheel，确认实际 import 来自 site-packages。验证版本、命令帮助、未收尾列表、命名服务状态、停止浏览器元数据、protocol show、三个 skills show、三个指南各 compact/browser/cases/full（12 种 JSON 读取组合）、文本主题和发行说明范围；版本及文档摘要一致，精简模式不展开详细主题。
- 完整导出包含 14 个资源且与安装包一致。修改导出内容后再次导出被拒绝，所有文件保持不变，status 能识别项目修改。只读包文档命令无需工作区，也不创建业务运行；测试只在临时目录写入受控数据。

## 同机查询性能

2026-11-05，Windows / Python 3.12.6，仓库外分别安装 0.12.7 与 0.12.8 wheel，依赖版本一致。同一临时工作区、同一份 7,200 条完成历史加 1 条失效占用、18 个服务，调用 `Services.status(probe=False)`；不执行健康检查，也不启动真实服务。两种配置分别按旧→新→新→旧顺序测量，计时包含历史读取、身份检查与状态组合，不包含解释器启动。以下不代替计算次数断言。

| 服务身份配置 | 0.12.7 两次耗时（秒） | 0.12.8 两次耗时（秒） | 两次均值变化 | 均值降幅 |
| --- | --- | --- | --- | --- |
| 默认工作区身份，未设置 resource_id | 45.028 / 88.015 | 1.676 / 1.919 | 66.521 → 1.797 秒 | 97.3% |
| 显式共享 resource_id | 3.730 / 2.319 | 1.695 / 1.782 | 3.025 → 1.738 秒 | 42.5% |

两组中，资源集合计算均从 **129,618 次降到 18 次**，操作进程检查从 **7,201 次降到 1 次**。默认身份原先反复解析工作区路径，达到本次减少至少 80% 的目标；显式共享 ID 原本就跳过这部分身份路径计算，因此改善幅度较小，不能把 97.3% 推广为所有配置的承诺。完成历史仍逐条读取，故文件读取仍有成本，没有为追求计时结果新增索引或跨命令缓存。两次采样、合成记录、无实际受管进程与跳过健康检查均限制了结论；不等于真实业务的总验收时间会减少同样比例。源码指纹去重由受控调用次数测试另行验证。

基线为本地已构建的 0.12.7 wheel，SHA-256：`fdd94b9809869ac04fa9ee2fe0aff1b3ec1a33cca0ef7281164ee84863e775c3`。新旧测量均使用安装包代码，不使用源码目录导入，也不读取或修改业务项目的实际记录。

## 指南场景核对

以下是随包内容的静态场景核对，不表示已对所有 Agent 宿主完成实际行为测试。

| 场景 | 指引结果 |
| --- | --- |
| 人工检查小改动 | 准备服务和业务 URL；无需固定脚本或 Docker 会话，未反馈时不报通过 |
| AI 一次性交互 | 复用已有入口和环境；最小连接、身份、登录通过后做关键操作、必要截图和收尾 |
| 容器可连但项目 Playwright 不兼容 | 检查实际脚本的导入来源／版本；修复失败前置点，再跑完整流程 |
| 登录／代理／目标身份不符 | 修复并复查该点，不默认另搭登录、API 或数据库 |
| 页面选择器或样式返工 | 可用明确标注的受控回复验证页面流程，不将其当真实模型质量证据 |
| 模型首次探索 | 少量代表样本确认协议、单位、引用和保存后再扩大；提前说明预计任务量 |
| 确认暂态故障 | 按现有适用策略考虑重试，报告真实请求与重试次数 |
| 单位／引用／契约结构错误 | 停止无法靠同一输入修复的样本并诊断，保留失败和未完成证据 |
| 已约定正式对照 | 不悄悄更改项目重试或对照策略；说明策略变更并按授权执行，报告实际耗时和用量，缺失值标未知 |
| 仍执行旧版指南 | 核对该次运行版本和离线开关来源；普通命令读取当前指南，显式离线只用于确实离线或指定包验收 |

本轮未调用真实模型、业务认证或真实 Docker 浏览器；未验证 macOS 及任意宿主的交互工具兼容性。本机全局入口升级未包含在此次提交发布操作中；已有项目导出副本需导出到空目录比较合并，不自动覆盖。
