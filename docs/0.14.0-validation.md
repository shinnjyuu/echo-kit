# 0.14.0 验证记录

本记录整理于 0.14.0 发布前，覆盖快速视觉观察入口。测试使用临时工作区、独立 Kit 数据目录、受控页面和测试创建的服务及容器。实际发布状态以[官方 PyPI](https://pypi.org/project/shinnjyuu-echo-kit/0.14.0/)为准。实际业务项目接入和真实账号认证另行验证。

## 已实现

`browser observe` 提供常驻 UTF-8 JSON 行协议，支持 observe、navigate、reload、close。默认观察当前自有页面，保持登录、弹窗和未保存输入。项目 Python 脚本通过 `serve_observer` 补充准备、就绪和诊断回调。随包提供 Node 管道客户端及匹配请求 ID 的回执读取入口。

观察会话复用现有服务、浏览器、operation、进程追踪和急停取消代次。正常关闭、EOF 和可确认的中断执行上下文收尾并保留 trace。急停取消本地观察后可以重新发起会话，项目标记的待清理业务状态继续保留。

## 同机性能

使用 Windows、本机 Docker、已缓存的浏览器镜像，关闭自动打开观看标签。下列数据来自不同的受控采样，不能合并为同一次请求。

| 场景 | 实测 |
| --- | --- |
| 一万行 DOM、打开弹窗及持续流式连接，十次热态观察 | p50 265.5ms，最近秩 p95 312ms |
| 简单页面的一次会话准备 | 4406ms |
| 简单页面的一次 worker 观察 | 78ms |
| Node 请求至收到响应 | 98.38ms |
| Node 读取本次 PNG | 2.42ms |
| 宿主图片读取工具读取已保存的受控截图 | 15ms |

worker 按响应记录就绪、截图和本机文件读取耗时。原始十次样本、客户端计时及受控截图保留于本机忽略目录 `.echo-kit/validation-0.14.0/`。宿主图片读取测试使用已经保存的截图，未测量从工具请求直至模型接收图片的完整端到端耗时。AI 推理时间及视觉 token 用量未知。性能数字只适用于这些受控页面与本机条件。
