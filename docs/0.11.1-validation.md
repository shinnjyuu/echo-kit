# 0.11.1 自动更新并发修复验证

状态：实现完成，待提交、推送及发布。实施时官方 PyPI 的 0.11.1 查询返回 404，尚未占用。本机 uv tool 安装入口仍为 0.10.0；本轮没有替换全局安装，发布后需升级该入口才能获得修复。

## 已验证

- 更新检查锁最多等待 3 秒；等待者重读并复用同轮完成结果，超时也重读缓存。真实文件锁配合事件验证首次检查成功、失败及竞争；受控子进程验证持锁进程被终止后锁可释放。
- 缓存新版、没有发行元数据但有准备记录、网络失败、uv 缺失、准备失败后选择之前版本，以及在线刷新失败但同一版本仍可离线使用。成功确认当前入口为最新时，不使用过时的准备记录。
- 子命令帮助转发、本地诊断不转发、显式离线保持当前包、解析错误补充更新指引、转发元数据被消费、业务失败只执行一次。
- Windows 完整核心回归：242 passed、9 skipped；随后补充版本选择边界，最终更新与文档专项：44 passed。未为最后一个边界测试重复整个 Windows 回归。
- Linux 最终完整回归：246 passed、6 skipped。使用一次性核心测试容器，安装本轮 wheel 后运行。早期尝试因镜像残留旧包导致隔离导入失败，安装新包后解决；另有两次全套出现既有服务启动测试 `test_partial_startup_and_timeout_preserve_state` 的进程提前退出，该用例单独复核通过，最终全套也通过，未改服务逻辑，偶发根因未确认。Linux 单独更新专项与该服务用例合计 34 passed。
- 仓库外独立环境安装最终 wheel，更新专项：33 passed。三个 Skill 校验通过；协议副本完全一致；91 个本地文档链接目标存在。
- 构建 wheel 与源码包成功。安装包指南、更新说明可读取，完整导出的资源与安装包逐字节一致。
- 仓库外创建独立的 0.11.2 测试包和环境，6 个并行调用从修复版真实转发到测试新版，返回该版本的输出；子命令帮助也验证通过。测试只替代发行数据和目标环境定位，实际版本探测、文件锁、CLI、子进程及防循环逻辑保持真实。测试包仅在临时目录，不上传任何包源。这不等于已验证生产 PyPI 安装。

## 发布后验收

获得发布授权后，验证正式 PyPI 包，再通过官方源升级 uv tool 入口；检查 PATH 命中的 echo-kit 及版本。使用临时工作区并行执行只读命令，验证实际版本与指南、帮助一致。不能只发布新版而保留有缺陷的旧入口。

本轮未启动真实业务服务或浏览器，未修改业务配置。完整核心测试使用受控测试进程。四个原有服务协调文件的未提交修改保持不变，未混入本轮修复。
