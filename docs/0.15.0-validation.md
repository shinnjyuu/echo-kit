# 0.15.0 资源用量验证

这是资源用量阶段的验证记录；同一版本的磁盘回收能力和最终安装包记录见[磁盘回收验证](0.15.0-storage-validation.md)。下文 wheel 摘要对应资源用量阶段。

状态：资源用量阶段的实现与安装包验证完成。2026-11-16 发布前查询官方 PyPI 时，最新为 0.14.0，0.15.0 尚未占用。正式发行与后续磁盘回收功能合并发布；本阶段未更新正式工具入口或业务项目。

## 交付能力

新增 `resources status [SERVICE...]`、全局 `resources status --all`、JSON、简短表格及分页。查询直接读取登记，不执行服务健康检查或源码指纹。共享实例与物理进程身份去重，嵌套受管根分别归属；引用工作区与操作占用分开，观察会话等没有 run_id 的操作也会显示。未收尾状态读取失败时保留有效用量并明确标记占用未知。

本机 RSS／Working Set 与 Docker CLI 内存分开汇总，CPU 采用实际间隔，未知值不当成零。完整容器 ID、所属本机引擎和工作区标签经过核验；多个容器批量统计，Docker 共享三秒预算。外部、不明归属和无标签容器不参与受管统计。

Windows 使用每轮一次的进程父子关系快照，之后仅采样已核验根及其后代。读取时仍检查 PID、创建时间、可执行文件、命令摘要及当前用户归属；终止进程的原有严格检查保持默认行为。资源采样不重复获取每个进程的全系统父进程表或线程暂停状态。

Windows 托盘增加只读资源摘要、内存最高的三个服务及明细。菜单仅读取内存快照，资源线程单轮执行，急停保持独立。旧托盘在安装后通过 `tray stop`、`tray start` 载入新菜单。

## 核心与安装包验证

- Windows / Python 3.12.6 全量核心回归：352 passed、20 skipped。随后补充无标签容器保护，最终 wheel 在仓库外的资源、文档、指南和导出专项：38 passed。
- 最终 wheel 在不联网、源码只读挂载的 Linux / Python 3.12 容器中完整回归：357 passed、16 skipped。核心资源模块未加载 Windows GUI 依赖。
- 覆盖统一 CPU 等待、每帧一次父进程快照、嵌套根与进程去重、PID 复用、真实进程树、外部实例、损坏登记、占用读取失败、依赖占用隔离、分页全范围汇总、工作区／环境和旧登记只读兼容。
- 一轮并发启动回归出现 Windows 临时文件访问拒绝。元数据原子替换增加仅针对 WinError 5/32 的有限重试：最多等待五次，每次 10ms；不重跑业务命令。确定性测试验证暂态恢复、永久错误仍返回以及旧内容保留；后续完整核心回归通过。
- 三个 Skill 头字段校验通过；12 份当前说明中的 136 个本地链接及锚点有效。公开协议与随包副本逐字节一致。
- 从仓库外的隔离 Windows 环境确认 import 来自 site-packages，实际安装入口的离线版本、无工作区全局 JSON、表格和帮助通过。三个指南的精简、services/browser 主题及完整模式均可读取；实际导出与协议一致，已有项目修改不会被覆盖。
- 最终 wheel SHA-256：`19cf6efd6e0b856278f12492dc399403c5d1248b18ddb63e3d072368af922a26`。wheel 包含资源模块与跨平台发现索引，没有临时验证脚本、废弃模块或 pyc。

## 单独的真实 Docker 与 Windows 托盘证据

- 真实 Docker 资源测试 1 项通过：创建三个本轮专用 Node 容器，核对两个所属容器的批量用量、第三个标签不符时不查询其 stats，以及停止和暂停状态。仅按本轮 create 返回的完整 ID 清理，不操作其他容器。这是容器统计证据，不是 Chromium 页面验收。
- 原生 Windows 托盘集成 2 项通过：独立启动方退出后，真实图标事件循环仍可调用已登记急停菜单回调；用同步信号阻塞资源采样时，菜单回调和急停仍完成。只终止隔离测试服务，测试托盘随后退出。
- 单服务托盘预热后，4.985 秒观测窗口内进程 CPU 增量 0.0781 秒；RSS 从 53,157,888 到 53,190,656 字节。这是包含原有状态轮询和 GUI 的整个测试托盘进程，不能当成仅新增采样的成本。
- **人工菜单外观、真实鼠标点击、观看页恢复和关键截图仍未验证。** 当前桌面有其他应用权限提示，桌面控制工具没有提供可操作的任务栏窗口。原生回调测试不替代人工点击，也不声称已拍到新菜单。

## 同机性能与范围

在独立 Kit 数据目录中启动 18 个轻量 Python 服务，每个保留 4 MiB 缓冲区；Windows 启动器实际形成 36 个进程。添加 7,200 条已完成历史和 1 条未收尾操作，连续查询三次；测试后结束这些进程并移除临时工作区。

| 指标 | 结果 |
| --- | --- |
| 无历史的一次完整查询 | 371.59 ms |
| 有历史的三次完整查询 | 2,361.61 / 1,668.16 / 1,879.44 ms |
| 有历史的查询中位数 | 1,879.44 ms |
| 三次采样阶段耗时，包含统一 250ms 等待 | 391 / 344 / 328 ms |
| 每次未收尾记录的进程描述次数 | 1；已完成历史为 0 |
| 每次显式 RSS 读取次数 | 72，即 36 个实际进程各采样两次 |
| 每次 CPU 采样等待次数 | 1 |
| 托盘复用现有登记／操作快照后的三轮增量采样 | 墙钟 0.216 秒、CPU 0.156 秒、采样宿主 RSS 净增长 0 字节 |

完整查询仍需读取现有操作历史文件；本轮没有引入持久化操作索引。托盘复用原有状态轮询已读取的未收尾快照，资源线程不再次遍历这些历史。增量采样数据不包含 GUI、Docker 或原有状态轮询，不能与整进程成本混为一项。开发初版逐服务读取父进程关系，单帧 profile 约 2.126 秒；改为统一快照后同类 profile 约 0.047 秒。

数字只适用于本机受控条件，测试期间机器还在执行其他验证，不承诺所有机器固定耗时或内存。原始测量、安装包记录、Linux XML 和原生托盘记录保留于本机忽略目录 `.echo-kit/validation-0.15.0/`。macOS、真实业务负载、远端 Docker 及长期监控不在本次验证范围内。
